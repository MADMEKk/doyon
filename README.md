# Partnership & Multi-Group Financial Management System
## نظام إدارة الشراكة المالية ومساحات العمل المتعددة (Multi-Group Workspaces)

نظام متكامل، آمن واحترافي لإدارة مالية الشراكات والمالية الشخصية عبر **مساحات عمل ومجموعات مالية متعددة ومستقلة تماماً (Multi-Group Architecture)** مع واجهة باللغة العربية ودعم كامل للاتجاه من اليمين إلى اليسار (RTL).

---

### 1. بنية مساحات العمل والمجموعات المالية (Multi-Group Architecture)
- **المجموعة المالية (`FinancialGroup`) هي الوحدة التنظيمية الأساسية:**
  - كل مستخدم يستطيع إنشاء وامتلاك والانضمام إلى مجموعات متعددة (مالية شخصية خاصة، شراكة أعمال، مشروع أ، مشروع ب).
  - **العزل المالي الصارم (Group-Isolated Financial Data):** كل حساب مالي، حركة نقدية، دين، قرض، شريك، مشروع، وتسوية ينتمي حصرياً لمجموعة واحدة فقط.
  - **منع التسميم العابر بين المجموعات (Anti Cross-Group Poisoning):** يتم التحقق على مستوى الخادم من أن الحساب البنكي، المشروع، الشريك وجهة الاتصال تنتمي جميعاً لنفس المجموعة عند تسجيل أي معاملة لمنع ثغرات IDOR والتلاعب.
- **نظام الأدوار والصلاحيات المستقل لكل مجموعة (`GroupRole`):**
  - **المالك (`OWNER`):** تحكم كامل بالمجموعة، إدارتها وحذفها.
  - **المدير (`ADMIN`):** إدارة الأعضاء والدعوات وضبط الإعدادات والعمليات المالية.
  - **المحاسب (`ACCOUNTANT`):** تسجيل ومراجعة المعاملات واستخراج التقارير.
  - **العضو (`MEMBER`):** إضافة والاطلاع على العمليات المصرح بها.
  - **المشاهد (`VIEWER`):** صلاحية قراءة فقط دون القدرة على التعديل أو الصرف.
- **إدارة الأعضاء والدعوات (`GroupInvitation`):**
  - إرسال دعوات عبر البريد الإلكتروني أو اسم المستخدم مع دور محدد وقبول/رفض مباشر.
  - محفظة/مساحة شخصية خاصة لكل مستخدم افتراضياً معزولة عن أي شراكة تجارية.

### 2. المبادئ المحاسبية والمالية المطبقة
- **دقة الحسابات النقدية والكسور:** استخدام `Decimal` لجميع الحسابات النقدية.
- **العمليات الذرية (`transaction.atomic`):** لضمان سلامة الأرصدة وتفادي تضارب البيانات.
- **الفصل بين الإيراد والاقتراض:** مبالغ القروض المستلمة لا تُحسب إطلاقاً كإيراد نشاط أو أرباح.
- **الفصل بين المصروف وسداد القروض:** سداد أصل الدين يقلل النقدية والالتزام دون تسجيله كمصروف تشغيلي مشوه للأرباح.
- **استقلالية حساب الأرباح عن التدفقات النقدية:** الأرباح التشغيلية تُقاس بالفارق بين الإيرادات والمصروفات، بينما حركة رؤوس الأموال والسحوبات الشخصية تؤثر فقط على حقوق الملكية.
- **سجل التدقيق والرقابة (`AuditLog`):** تسجيل تلقائي لكافة الحركات مع هوية المستخدم والمجموعة والوقت.

### 3. التثبيت والتشغيل المحلي (Local Setup)

1. **المتطلبات الأساسية:**
   - Python 3.11+
   - pip

2. **تثبيت الحزم:**
   ```bash
   pip install -r requirements.txt
   ```

3. **إعداد ملف البيئة:**
   قم بنسخ `.env.example` إلى `.env`:
   ```bash
   cp .env.example .env
   ```

4. **تطبيق ترحيل قاعدة البيانات:**
   ```bash
   python manage.py migrate
   ```

5. **توليد بيانات البداية والمجموعات الافتراضية:**
   ```bash
   python manage.py seed_initial_data
   ```
   **بيانات تسجيل الدخول الافتراضية:**
   - **الشريك الأول:** اسم المستخدم `partner1` | كلمة المرور `Partner2026!`
   - **الشريك الثاني:** اسم المستخدم `partner2` | كلمة المرور `Partner2026!`

   *(يمتلك كل منهما مجموعة مالية شخصية خاصة، بالإضافة إلى عضويتهما في مجموعة شراكة الأعمال المشتركة).*

6. **تشغيل خادم التطوير:**
   ```bash
   python manage.py runserver
   ```
   افتح المتصفح على: `http://127.0.0.1:8000/`

7. **تشغيل الاختبارات الآلية (Test Suite):**
   ```bash
   python manage.py test
   ```

### 4. متطلبات التخزين الدائم والنشر المجاني (Deployment Guide)

> [!IMPORTANT]
> **تحذير حاسم بشأن استمرارية قاعدة البيانات:**
> إن منصات الاستضافة المجانية السحابية (مثل Render Free أو Koyeb) توفر حاويات بنظام ملفات سريع الزوال (**Ephemeral File System**).
> أي قاعدة بيانات SQLite محلية ستُفقد بالكامل عند كل إعادة تشغيل تلقائي للحاوية!
> لحماية السجلات المالية للشراكة من الضياع، يجب استخدام قاعدة بيانات سحابية مستمرة ودائمة مجانية.

#### البنية الموصى بها للاستضافة المجانية المضمونة:
1. **قاعدة البيانات المجانية الدائمة:**
   - استخدم خطة **Neon PostgreSQL Free Tier** أو **Supabase Free PostgreSQL**.
   - انسخ رابط الاتصال:
     `postgres://user:password@ep-xyz.neon.tech/neondb?sslmode=require`
2. **استضافة تطبيق Django المجانية:**
   - منصة **Render.com** (Web Service مجاني) أو **Fly.io** أو **Koyeb**.
3. **متغيرات البيئة للإنتاج على منصة الاستضافة:**
   - `DEBUG`: `False`
   - `SECRET_KEY`: مفتاح إنتاج عشوائي قوي
   - `ALLOWED_HOSTS`: نطاق التطبيق الخاص بك (مثل `your-app.onrender.com`)
   - `DATABASE_URL`: رابط قاعدة بيانات Neon أو Supabase PostgreSQL.
   - `CSRF_TRUSTED_ORIGINS`: `https://your-app.onrender.com`
4. **أمر البناء والبدء (Build & Start Commands):**
   - **Build Command:**
     ```bash
     pip install -r requirements.txt && python manage.py collectstatic --noinput && python manage.py migrate
     ```
   - **Start Command:**
     ```bash
     gunicorn config.wsgi:application
     ```
